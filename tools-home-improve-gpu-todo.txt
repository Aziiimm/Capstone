What this branch is trying to accomplish
----------------------------------------
The engineer appears to be turning an Amazon Reviews 2023 data-processing prototype into a GPU-accelerated recommender workflow for Tools and Home Improvement, then expanding it to multiple categories.

Main goals visible in the branch:

1. Build a RAPIDS GPU data pipeline.
   - Load Amazon review JSONL data with Dask/cuDF.
   - Standardize the Amazon 2023 schema into the project schema:
     reviewerID, asin, rating, reviewText, timestamp.
   - Join review rows to metadata through parent_asin.
   - Filter down to users with at least 6 reviews and items with at least 11 reviews.
   - Write the final 7-column Parquet output:
     reviewerID, asin, rating, reviewText, timestamp, product_title, main_category.

2. Make the pipeline run across multiple categories.
   - Add categories.json with Tools_and_Home_Improvement, Industrial_and_Scientific, and Sports_and_Outdoors.
   - Add data/run_multicategories.py to process each category sequentially.
   - Use Dask-CUDA, RMM memory pools, and VRAM cleanup between categories.
   - Save a summary file at output/multi_run_summary.json.

3. Add GPU model training.
   - Add models/new_model.py to train a cuML NearestNeighbors recommender.
   - Build one global user/item integer mapping across one or more Parquet inputs.
   - Build an item-by-user sparse matrix on GPU.
   - Save a pickled AmazonRecommenderGPU object.

4. Add interactive inference.
   - Add models/inference.py to load models/full_recommender.pkl.
   - Search product titles by text.
   - Run nearest-neighbor inference and print similar product titles.

5. Capture performance experiments.
   - The branch contains timing outputs and notes showing successful limited runs.
   - The previous notes mention that full Tools_and_Home_Improvement runs had write-stage hangs/deadlocks or long stalls.

Important branch risks and gaps
-------------------------------
1. This branch has no merge base with main in the local checkout, so it needs careful reconciliation before it is merged or used as a PR.

2. Compared with main, this branch deletes important project files:
   - .gitignore
   - README.md
   - docs/PLAN.md
   - weekly check-ins
   - tests/test_filter.py

3. Generated or local-only files are committed:
   - data/__pycache__/*
   - models/__pycache__/*
   - cufile.log
   - output/multi_run_summary.json
   - output/timings.json
   - =12.0.0
   - test.txt

4. There are many untracked local artifacts:
   - dataset/*
   - output/*.parquet
   - output/timings_*.json
   - cpu/__pycache__/*
   - gpu/__pycache__/*

5. data/run_pipeline.py imports cudf at module import time. That can break CPU-only environments before the code reaches the optional GPU checks.

6. data/run_multicategories.py uses local imports like "from load import load". That works only in some invocation styles and may fail with "python -m data.run_multicategories".

7. GPU memory settings are hard-coded and inconsistent.
   - run_pipeline.py says 7GB in the comment but initializes 8GB.
   - run_multicategories.py hard-codes a 20GB pool and mentions TITAN RTX, which will not fit on an 8GB RTX 3060 Ti.

8. The timing numbers are misleading because Dask is lazy. The near-zero filter times likely measure graph construction, while actual work happens during the Parquet write.

9. The metadata join may not scale. load.py computes the full metadata dataframe before joining in the full-data path, which can exhaust host or GPU memory on large categories.

10. to_parquet.py assumes metadata columns always exist. Running without --meta can fail because product_title and main_category are required in FINAL_COLUMNS.

11. models/new_model.py and models/inference.py are prototypes.
    - The model path is hard-coded in inference.py.
    - Inference output has encoding/mojibake issues.
    - The recommender returns titles only, with no ASINs, scores, or category context.
    - Pickling a cuML model plus GPU sparse matrix may not be portable across environments.

12. requirements.txt mixes RAPIDS, CUDA, and CuPy assumptions. The file named =12.0.0 appears to be accidental pip output from installing cupy-cuda11x.
